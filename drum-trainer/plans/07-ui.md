# 07 — UI

## Principles

- **Stock MUI, dark theme, zero custom design.** `createTheme({ palette: { mode:
  'dark' } })` and default components throughout. The only visual flourish is the
  timing meter, which is a functional display, not decoration.
- **Practice-distance readable.** The user is behind a drum kit, meters from the
  screen. Live-screen numbers use large typography (`h1`/`h2` variants); controls
  are big; nothing on the live screen requires precision clicking.
- **React state stays in `ui/`.** Audio modules are wrapped by one hook
  (`useSessionRunner`) — components never touch Web Audio directly.

## Navigation

Four screens, MUI `Tabs` (Practice · History · Settings) + a modal flow for the
live session. No router dependency — a `useState<Screen>` switch is enough for
four screens; React Router is explicitly rejected as unjustified weight.

## Screens

### SetupScreen (default tab: Practice)

- BPM: slider + numeric input (40–240)
- Subdivision: `ToggleButtonGroup` — 1/4, 1/8, triplet, 1/16
- Duration: preset chips (30s / 1m / 2m / 5m) + custom
- Label: free-text `Autocomplete` seeded with previously used labels
- Calibration status line: "Calibrated: 23 ms ✓" or warning + Calibrate button
- Big Start button. Disabled with a reason if mic permission is denied.
- First-run: a `MicCheck` panel (input level bar + hit flash + sensitivity
  slider) so detection is verifiably working before the first session.

### LiveScreen

Mirrors the eDrumTrainer layout (see project screenshot):

- Count-in ("4… 3… 2… 1…"), then elapsed/remaining time (`h1`) + `LinearProgress`
- **TimingMeter**: horizontal bar, EARLY ←—|—→ LATE, center = on the beat.
  A marker per hit at `offsetMs`, colored by |offset| (green → yellow → red),
  fading over ~1 s. Implemented as absolutely-positioned divs with CSS
  transitions — cheap, and intentionally not a chart library concern.
- Session config summary (label, BPM, subdivision, duration) in small text
- Stop button (ends early; partial session still scored and saved with actual
  elapsed duration)

Screen wake-lock (`navigator.wakeLock`) requested during a session, released
after — a sleeping laptop mid-session otherwise kills the mic stream.

### SummaryScreen

- Stat cards (`Card`): mean offset (with "rushing/dragging" plain-language
  interpretation), std dev, hit rate, stray hits / missed beats
- Session-detail scatter + histogram (see 06)
- Buttons: Save & finish (default), Discard, Practice again (same settings)

### HistoryScreen

- Filters: label (`Autocomplete`), BPM range
- Improvement-trend chart (see 06)
- Session table (`Table`): date, label, BPM, subdivision, duration, stdDev,
  mean offset, hit rate; row click → session detail view; delete with confirm
- Export / Import buttons

### Settings (small tab)

- Calibrate (with guided flow: "turn up speakers, stay quiet, 8 clicks…")
- Detector sensitivity (slider + live MicCheck)
- Accuracy window (ms)
- Danger zone: clear all data (double-confirm)

## `useSessionRunner` (the one nontrivial hook)

State machine: `idle → countIn → running → scoring → done`, exposing
`{ phase, elapsed, lastOffsets, start(), stop() }`. Owns metronome + detector
lifecycles and guarantees cleanup (mic released, worklet node disconnected) on
unmount/stop — the classic leak in Web Audio React apps.

Hit events arrive off-React; the hook batches them into state via a ref +
`requestAnimationFrame` flush so a 1/16-note flurry doesn't trigger a render
per hit.

## Accessibility / plumbing notes

- All controls are labeled MUI inputs; meter has an `aria-live` text alternative
  ("12 ms late") updated at most 1×/s.
- Mic permission denial, no-input-device, and AudioContext-suspended states all
  render as visible `Alert`s with recovery instructions — no dead silence.
